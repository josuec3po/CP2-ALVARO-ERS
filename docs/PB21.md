## Regras

- `C_modulos = preco_brl * quantidade_modulos`.
- `C_inversor = preco_brl` do inversor selecionado (1 unidade).
- `C_baterias = preco_brl * quantidade_baterias`; sem armazenamento, zero.
- `C_equipamentos = C_modulos + C_inversor + C_baterias`.
- `C_demais = C_equipamentos * percentual_adicionais / 100`.
- `C_total = C_equipamentos + C_demais`.
- Custos adicionais: 20% por padrão, conforme exemplo do cartão T02;
  configuráveis entre 0% e 100% nesta versão.
- Valores monetários são calculados com `Decimal`. Cada parcela e os adicionais
  são arredondados em centavos, com empate arredondado para cima. O total é a soma
  das parcelas exibidas, evitando diferenças entre o relatório e o cálculo.
- Potência instalada: `potencia_wp * quantidade_modulos / 1000`, em kWp.
- Capacidade nominal total: `capacidade_kwh * quantidade_baterias`.
- Capacidade útil total: capacidade nominal total multiplicada por `dod_pct / 100`.

Entradas devem ser finitas. Preços e adicionais aceitam zero; quantidades devem
ser inteiras positivas. Consumo, HSP, potências, capacidade e DoD devem ser positivos.
HSP é limitada a 24 h/dia; percentuais atendido e DoD a 100%. Campos obrigatórios
vazios, negativos, NaN e infinito são rejeitados. Vírgula decimal é aceita.
A potência instalada deve atender à calculada.

## Contrato de integração com PB17-20

`gerar_proposta` recebe os equipamentos **já selecionados**. Os dicionários usam
os mesmos nomes de campos dos CSVs presentes em `feature/pb17-fornecedores`:

| Objeto | Campos obrigatórios |
| --- | --- |
| Módulo | `fabricante`, `modelo`, `preco_brl`, `potencia_wp` |
| Inversor | `fabricante`, `modelo`, `preco_brl` |
| Bateria, se incluída | `fabricante`, `modelo`, `preco_brl`, `capacidade_kwh`, `dod_pct` |

```python
from orcamento import gerar_proposta, resumo_proposta

# Dados fictícios para testar a apresentação; não são uma seleção técnica.
modulo = {"fabricante": "Painel Teste", "modelo": "P550",
          "preco_brl": "589.00", "potencia_wp": "550"}
inversor = {"fabricante": "Inversor Teste", "modelo": "I5000",
            "preco_brl": "2599.00"}
proposta = gerar_proposta(410, 100, 5, "3.42", modulo, 7, inversor)
print(resumo_proposta(proposta))
```

O retorno é um dicionário com dados técnicos, equipamentos, capacidades,
custos parciais, percentual de adicionais e total. A função não modifica os
dicionários recebidos e não depende de MySQL.

Na consulta atual, `main` contém o console de consumo e o CRUD MySQL. A branch
`fature/-pb-19-20` foi criada, mas ainda tem o mesmo conteúdo de `main`, sem funções
de dimensionamento. A branch de PB18 também não fornece uma função
de dimensionamento. Por isso, esta entrega disponibiliza a integração por função
e a entrada manual dos resultados prévios. Quando as funções de PB18-20 estiverem
disponíveis, elas podem chamar `gerar_proposta` diretamente.

O consumo reaproveitado de `main.py` é uma estimativa mensal dos equipamentos,
não o máximo de um histórico mensal. A execução independente permite informar o
consumo de referência definido pelas histórias anteriores.
